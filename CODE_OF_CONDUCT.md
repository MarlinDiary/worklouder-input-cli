# Code of conduct

## Our standard

WorkLouderCTL contributors and maintainers are expected to be respectful,
constructive, precise about evidence, and considerate of different experience
levels. Harassment, discrimination, threats, deliberate exposure of private
configuration data, and sustained disruptive behavior are not acceptable.

Technical disagreement is welcome. Critique behavior, code, contracts, and
evidence rather than people. Compatibility and hardware claims should name
their tested boundary, and corrections should be handled without hostility.

## Scope

This standard applies in repository issues, pull requests, reviews, discussions,
release channels, and other project spaces. It also applies when someone is
representing the project in public.

## Reporting and enforcement

Report ordinary conduct concerns to the maintainer through the repository's
issue tracker. Use GitHub private vulnerability reporting when a report includes
credentials, private configuration, device identifiers, or another security-
sensitive detail.

Maintainers may edit or remove content, close or lock discussions, reject
contributions, or temporarily or permanently restrict participation. Reports
will be reviewed in context, kept as private as the available channel permits,
and handled consistently with the severity and persistence of the behavior.
